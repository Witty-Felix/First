## 1. 红绿灯指示的放置位置

### ① 待实现功能

通过 RGB 灯带直观反映系统运行状态——有障碍物亮红灯、无障碍物亮绿灯。

### ② 错误代码

```c
// main.c  while(1) 中
while (1)
{
    if(!Obstacle_Flag)
        LED_Show_Green();
    else
        LED_Show_Red();

    /* 10ms 一次采集数据 */
    if(Timer_Poll_Flag == 10) { ... RS485_U1_Poll(); }
    Motor_Check_State(&Motor);
}
```

### ③ 错误原因

- **每次循环都阻塞 ~28ms**：`LED_Show_Green/Red()` 内部通过 `RS485_U2_SendArray` 发送 21 字节，9600 波特率下耗时约 28ms（含两个 `Delay_ms(3)`），且是阻塞发送（等 TXE/TC 标志）。
- **主循环被拖慢**：雷达轮询 `RS485_U1_Poll()` 每 10ms 触发一次，被 28ms 阻塞后实际间隔被拉长到 30~40ms+；电机状态机调用频率也从微秒级降到 ~28ms/次。
- **条件没变却重复发送**：障碍物标志没变化时，重复发送相同颜色指令毫无意义，白白浪费总线带宽。

### ④ 正确代码 / 解题思路

**思路：将红绿灯逻辑移到障碍物状态真正变化的地方——`Motor_Check_State()` 中，紧贴 `Obstacle_Flag` 赋值处调用，只在状态切换时发一次。**

```c
// Motor_Check_State() 中

/* 障碍物触发时 */
if(RADAR_RX_DIST <= OBST_MAX_DIST && RADAR_RX_DIST != 0)
{
    if(!Obstacle_Flag)
    {
        Motor_Stop();
        Obstacle_Flag = 1;
        LED_Show_Red();        // ← 只在 Obstacle_Flag: 0→1 时发
        ...
    }
}

/* 障碍物恢复时 */
if(s_RecoverCnt >= OBST_RECOVER_CNT)
{
    Motor_Resume();
    Obstacle_Flag = 0;
    LED_Show_Green();          // ← 只在 Obstacle_Flag: 1→0 时发
    ...
}
```

`main.c` 中只保留上电初始亮绿灯：

```c
printf("Motor Starts!\n");
LED_Show_Green();              // ← 初始状态亮绿灯，仅一次
```

## 2. 上电初始绿灯缺失

### ① 待实现功能

系统上电时默认无障碍物，RGB 灯带应显示绿色表示就绪。

### ② 错误代码

```c
// 初始代码中只有：
printf("Motor Starts!\n");
// 缺少 LED_Show_Green()
```

### ③ 错误原因

`Obstacle_Flag` 是全局变量默认值为 0，但从未调用过 `LED_Show_Green()`，RGB 灯带在上电后处于上一次残留颜色或灭灯状态，要等第一次遇到障碍物再恢复才会变绿。

### ④ 正确代码

```c
printf("Motor Starts!\n");
LED_Show_Green();              // ← 补上初始绿灯
```

## 3. 障碍物急停时未暂停时序

### ① 待实现功能

障碍物急停期间，时序应暂停。障碍物清除后，剩余等待时间继续计时，而不是把等待时间浪费在急停期间。

### ② 错误代码

```c
if(s_RecoverCnt >= OBST_RECOVER_CNT)
{
    Motor_Resume();
    Obstacle_Flag = 0;
    s_RecoverCnt  = 0;
    Stop_ms       = Timer_ms;    // ← 重置等待计时起点
    LED_Show_Green();
}
```

### ③ 错误原因

- **`Stop_ms = Timer_ms` 重置了计时起点**：假设在 MID_STOP 已等了 500ms，障碍物来了持续 3s，恢复后 `Stop_ms = now`，已经等待的 500ms 被清零，2 秒重新从头计。
- **障碍物前已等待的时间被浪费**：用户需要的是"等够 2 秒就走"，而不是"障碍物停了多久与我无关，我再等 2 秒"。

### ④ 正确代码 / 解题思路

**思路：急停时记录阻塞起点 `s_ObstacleStart = Timer_ms`；恢复时将阻塞时长补偿到 `Stop_ms` 中。**

```c
// 新增静态变量
static uint32_t s_ObstacleStart;   // 障碍物触发时刻

// 障碍物触发时
s_ObstacleStart = Timer_ms;        // ← 记录急停时刻

// 障碍物恢复时
Stop_ms += (Timer_ms - s_ObstacleStart);  // ← 将阻塞时长补偿到 Stop_ms
// 例：已等500ms + 障碍物3s，Stop_ms 被推后3s
// 等效于 (now - Stop_ms) = 500ms，还要再等1500ms → 正确！
```

## 4. 障碍物恢复时无条件调用 Motor_Resume()

### ① 待实现功能

障碍物清除后，仅在电机**原本正在运动中**才恢复脉冲输出；若电机原本就处于暂停等待态（如 MID_STOP），则不应恢复脉冲。

### ② 错误代码

```c
if(s_RecoverCnt >= OBST_RECOVER_CNT)
{
    Motor_Resume();        // ← 无条件恢复，不管当前是什么状态
    Obstacle_Flag = 0;
    ...
}
```

### ③ 错误原因

`Motor_Stop()` 只控制 TIM5 脉冲输出是否使能，但**为什么停**有两种不同场景：

| 场景 | 电机被停的原因 | 恢复时调 `Motor_Resume()` | 后果 |
|------|--------------|------------------------|------|
| **MID_STOP** 等 2 秒 | 状态机主动要求暂停 | 🚨 TIM5 重新输出脉冲 | **电机突然自己跑**，明明还在等 2 秒 |
| **WAIT_START** 等指令 | 等待串口命令 | 🚨 同上 | **没收到 START 就动了** |
| **GO_END** 正在前进 | 障碍物外力打断 | ✅ 正确恢复运动 | 正常 |

`Motor_Resume()` 本质是 `TIM_Cmd(TIM5, ENABLE)`，物理上真的会给步进电机发脉冲。

### ④ 正确代码 / 解题思路

**思路：根据 `g_RunState` 判断当前是否为运行态，仅在运行态才恢复脉冲。**

```c
if(s_RecoverCnt >= OBST_RECOVER_CNT)
{
    Stop_ms += (Timer_ms - s_ObstacleStart);

    if(g_RunState == HOME_CHECK || g_RunState == WAIT_HIT ||
       g_RunState == GO_END   || g_RunState == BACK_MID ||
       g_RunState == GO_BACK)
    {
        Motor_Resume();          // ← 仅运行态才恢复脉冲
        LED_Show_Green();
    }
    else
    {
        LED_Show_Yellow();       // ← 暂停态不恢复脉冲，亮黄灯继续采集
    }

    Obstacle_Flag = 0;
    s_RecoverCnt  = 0;
}
```

**运行态判定表：**

| `g_RunState` | 电机状态 | 恢复时操作 |
|-------------|---------|-----------|
| `HOME_INIT` | 未启动 | ❌ 不恢复，等状态机自行启动 |
| `HOME_CHECK` | 正在寻原点 | ✅ 恢复脉冲 |
| `WAIT_START` | 等待命令 | ❌ 不恢复 |
| `GO_MID` | 瞬态→WAIT_HIT | 不经过此判断 |
| `WAIT_HIT` | 正在前进 | ✅ 恢复脉冲 |
| `MID_STOP` | 暂停 2s | ❌ 不恢复 |
| `GO_END` | 正在前进 | ✅ 恢复脉冲 |
| `MID_STOP2` | 暂停 2s | ❌ 不恢复 |
| `BACK_MID` | 正在后退 | ✅ 恢复脉冲 |
| `MID_STOP3` | 暂停 2s | ❌ 不恢复 |
| `GO_BACK` | 正在后退 | ✅ 恢复脉冲 |
| `BACK_STOP` | 暂停 2s | ❌ 不恢复 |

## 5. RS485 能否改为非阻塞

### ① 待实现功能

评估将 RS485 发送从阻塞模式改为非阻塞（中断/DMA）模式的可行性、难点与必要性。

### ② 当前阻塞点分析

```c
void RS485_U2_SendArray(uint8_t* array, uint16_t length)
{
    GPIO_SetBits(GPIOD, PD7);       // DE 高 → 发送模式
    Delay_ms(3);
    for(i = 0; i < length; i++)
    {
        USART_SendData(USART2, array[i]);
        while(!TXE);                // ← 阻塞
    }
    while(!TC);                     // ← 阻塞
    Delay_ms(3);
    GPIO_ResetBits(GPIOD, PD7);     // DE 低 → 接收模式
}
```

| 函数 | 长度 | 9600 耗时 | 调用场景 |
|------|:----:|:---------:|---------|
| `U1_SendArray` | 8 字节 | ~14ms | 每 10ms 雷达轮询 |
| `U2_SendArray` | 21 字节 | ~28ms | RGB 灯带（仅状态切换时） |

### ③ 改非阻塞的三个麻烦

1. **DE 引脚时序敏感**：RS485 的 DE 必须在整个发送期间保持高电平。非阻塞要靠 TC 中断来判断"发完了"，在中断里切 DE 低。时序没算准，最后一个字节会丢失或冲突。

2. **需为两个 USART 各搭一套发送状态机**：
   ```
   申请发送 → 开 TXE 中断 → ISR 逐字节喂数据 →
   最后一字节 → 关 TXE → 等 TC 中断 → ISR 切 DE 低 → 置完成标志
   ```
   还要处理：发送中又来新请求怎么办？排队还是丢弃？

3. **本项目收益有限**：RGB 灯带已经改为只在状态切换时发（极低频），雷达 14ms 阻塞对步进电机 24ms 控制周期影响不大。

### ④ 结论

| 问题 | 回答 |
|------|------|
| 能改非阻塞吗？ | **能**，用 TXE/TC 中断或 DMA |
| 麻烦吗？ | **中等偏麻烦**，两个 USART 各要一套状态机 + DE 时序处理 |
| 在本项目有必要吗？ | **目前建议不改**。RGB 阻塞已降到极低频，雷达 14ms 阻塞对电机控制影响不大 |
| 如果将来一定要改？ | **优先只改 U1（雷达）**，U2（灯带）频率低不值得动。用 DMA 方式改动最小 |

## 6. 三色灯逻辑（黄/绿/红）

### ① 待实现功能

细化指示灯状态：电机暂停采集数据时亮黄灯，正常运行时亮绿灯，障碍物急停时亮红灯。

| 状态 | 灯色 | 含义 |
|------|:----:|------|
| 电机在暂停位等待（MID_STOP 等） | 🟡 黄 | 正在采集/处理数据 |
| 电机正常运行中 | 🟢 绿 | 畅行无阻 |
| 障碍物急停 | 🔴 红 | 危险！ |

### ② 错误代码

```c
// 有人尝试在 case 内加黄灯，但位置错了：
case MID_STOP:
    LED_Show_Yellow();          // ← 在 case 内、if 外，每轮循环都调！
    if((Timer_ms - Stop_ms) > 2000) { ... }
    break;

case MID_STOP2:
    LED_Show_Yellow();          // ← 同上，每轮循环都调
    ...
```

### ③ 错误原因

`LED_Show_Yellow()` 放在 `case MID_STOP` 的入口、`if` 条件之外，意味着 **2 秒等待期间每轮循环都调一次**，每次阻塞 ~28ms。这完全破坏了之前"只在状态切换时发一次"的优化成果，导致：

- 等待 2 秒期间，主循环被反复阻塞 28ms
- `RS485_U1_Poll()` 的 10ms 周期被严重打乱

### ④ 正确代码 / 解题思路

**思路：黄灯只加在进入暂停态的那一刻（状态切换时），绿灯只加在离开暂停态的那一刻。**

```c
/* 进入暂停态 → 🟡 黄灯（仅一次） */
case WAIT_HIT:
    if(Motor->Pulse_Count >= 2828)
    {
        Motor_Stop();
        LED_Show_Yellow();           // ← 到中点暂停
        g_RunState = MID_STOP;
        Stop_ms = Timer_ms;
    }
    break;

/* 离开暂停态 → 🟢 绿灯（仅一次） */
case MID_STOP:
    if((Timer_ms - Stop_ms) > 2000)
    {
        RS485_U1_Data_Print();
        LED_Show_Green();            // ← 继续前进
        Motor_Start(Motor);
        g_RunState = GO_END;
    }
    break;
```

四个暂停态（MID_STOP / MID_STOP2 / MID_STOP3 / BACK_STOP）均是此模式。

**完整生命周期：**

```
上电 ──🟢──→ 寻原点 ──🟢──→ 等待 START ──🟢──→ 前进
                      ↓ 到中点                  ↑
                    🟡 暂停2秒采集数据 ──🟢──→ 继续前进
                      ↓ 到终点                  ↑
                    🟡 暂停2秒采集数据 ──🟢──→ 返回中点
                      ↓ ...循环...

★ 任何时刻遇到障碍物 → 🔴 急停
   ├── 障碍物恢复时若在运行态 → 🟢 继续跑
   └── 障碍物恢复时若在暂停态 → 🟡 继续采集
```

**最终涉及文件清单：**

| 文件 | 改动 |
|------|------|
| `Src/main.c` | 初始化后加 `LED_Show_Green()`；移除 while(1) 中的红绿灯轮询 |
| `Src/bsp/Motor.c` | 新增 `s_ObstacleStart` 变量；障碍物触发/恢复处加红绿灯；状态切换处加黄/绿灯；恢复时条件化 `Motor_Resume()` |
